# Decision ledger

Every place where v1 differs from the spec or the Delphi reference, and every choice the
spec leaves open, is a row here. Each row names the plan section, the reason, and the test
that pins the behaviour (**Pinned by**). A row with an empty *Pinned by* has no
implementation yet. `plan.md` §0.3 (B1–B8) and §11.2 (D1–D18) are the master text; when
they disagree with this file, `plan.md` wins and this file is fixed in the same change.

Precedence (plan §0.3): B fixes → `docs/spec/MECHANICS.md` → D decisions → Delphi sources →
rest of the blueprint → `fastcopyw.cpp`.

## Added decisions (D19+)

Behaviour the spec did not settle, found while implementing. Each row has a pinning test.

| ID | Topic | Decision | Reason | Pinned by |
|---|---|---|---|---|
| D19 | Binary detection scope | A file without a BOM is binary when **any** NUL byte appears outside a UTF-16 pattern, found by scanning the whole file with `memchr` (Delphi probes only the first 64 KiB) | A NUL after 64 KiB still means the file is not text; the scan costs far less than a load | `core-text` `encoding::tests::nul_after_the_first_64k_still_makes_utf8_binary`, `nul_characters_make_a_file_binary` |
| D20 | UTF-16 without a BOM | Detected from the NUL pattern of the first 64 KiB: zeros in only one byte position (at most a quarter as many in the other), no `00 00` unit, and the units read as text (no control characters but TAB/LF/VT/FF/CR, no C1 controls, well-formed surrogates). The Delphi code never detects UTF-16 without a BOM | Windows tools write BOM-less UTF-16 (logs, registry exports); the text check stops a short binary blob with one NUL from being read as UTF-16 | `core-text` `encoding::tests::utf16_without_bom_is_found_by_the_nul_pattern`, `utf16_heuristic_handles_short_files`, `nul_characters_make_a_file_binary`; corpus files `utf16*_nobom__*` |
| D21 | UTF-8 validity and lossy loads | A file is UTF-8 only when the **whole** buffer passes strict `std` validation (no overlongs, surrogates or code points above U+10FFFF; Delphi `DcIsValidUtf8` is looser); otherwise the ANSI code page is used. Malformed UTF-16, or invalid bytes after a UTF-8 BOM, are decoded with U+FFFD and the document is marked *lossy*; a lossy document refuses to `serialize` | Never write back a file that was silently altered while loading | `core-text` `encoding::tests::invalid_utf8_falls_back_to_the_ansi_code_page`, `invalid_utf8_after_a_bom_is_decoded_lossily`, `document::tests::lossy_documents_refuse_to_serialize` |
| D22 | Custom line weights | A custom weight hook result below 0 is treated as 0 (= the default). The weight of an empty line is always 2 | The aligner assumes weights are positive; a hook must not be able to break run weighting | `core-text` `meta::tests::custom_weight_hook_replaces_the_default_base` |
| D23 | Side symmetry of the aligner | Swapping left and right is **not** an exact mirror: gap DP ties prefer pair, then *source* orphan, then target orphan (spec ALIGN-1.5), so equal-score alignments are chosen differently after a swap. Coverage, order and closeness are symmetric; the placement of orphans among equal-score choices is not | The spec's tie rule is asymmetric by definition; making it symmetric would change published row layouts. | D24 | Histogram candidate limit | A histogram anchor may occur at most 64 times in the range of `a`; with more, the range goes to Myers. | D25 | Work-stack depth for big runs (replaces the backlog "depth-10k test", E2-S7.1) | The block before a big run is a sub-rectangle of the window that found the run, so it cannot hold a big run itself (its start cell would have been visited first by the L-scan). | D26 | CRC-collision guard scope | Myers, Histogram and Patience confirm every match with comparable-text equality (`Aligner::confirm`). The Standard aligner follows the spec and trusts hash equality | A collision never pairs different lines in the exact kinds; Standard stays spec-exact for the model | `core-diff/tests/align_kinds.rs::a_crc_collision_never_pairs_different_lines_in_the_exact_kinds` (strings with equal CRC crafted by CRC forcing) |
| D27 | Delete and non-link reparse points | Delete removes SYMLINK, MOUNT_POINT and LX_SYMLINK entries as links and never traverses them. Directories with any *other* reparse tag (cloud placeholders, dedup, WCI) are regular and are traversed and deleted normally (D16). A new tag class that must not be traversed needs a new row | OneDrive folders must delete like folders; only real links are special | `core-vfs/tests/win32.rs::junctions_are_links_and_are_never_traversed_by_delete` |

| D30 | Folder rules: content worker limit | `FolderRules.content_workers` (default 4, 1 = serial) replaces the `parallel_content` flag of plan.md §7.1. | D35 | Rules-based content compare limits | Both files are streamed in 1 MiB blocks first (early stop, cancel between blocks). | D36 | Hidden/system and vanished folders in the scan | Hidden/system skipping (D18) is decided per pair, like filters, so attribute skew never leaves the visible twin as an orphan. | D37 | Recycle Bin implementation | `LocalWin32::delete(RecycleBin)` uses `SHFileOperationW(FO_DELETE, FOF_ALLOWUNDO | FOF_WANTNUKEWARNING)` on a dedicated single-threaded COM apartment thread instead of `IFileOperation`: windows-sys has no COM interface wrappers and the `windows` crate would be a new dependency for one call (this amends plan.md §6.3 and the E5-S7 wording). The shell deletes permanently what it cannot recycle, so before any shell call these are refused with `Unsupported`: a path of 260 units or more, non-local-drive paths, non-fixed drives, links, any name the shell would read differently from the listing (trailing dot or space, device name, wildcard or other invalid character), a policy `NoRecycleFiles`, a volume with `NukeOnDelete` set, and an item larger than the bin limit (`MaxCapacity` of the volume, else 10 % of the volume). `FOF_WANTNUKEWARNING` without `FOF_NOCONFIRMATION` is the last backstop: a permanent delete the checks missed makes the shell ask the user, so it is never silent.
